## 3. 入力トークンとLLM時間の関係

```
prompt_tokens     1,000増あたり LLM +5.29秒  （範囲 29,752〜31,243）
completion_tokens 1,000増あたり LLM +8.87秒  （範囲    451〜 1,618）
```

**単回帰の傾きは2つとも正だが、prompt と completion は往復の深さとともに同時に増えるため、
この2本の回帰だけでは切り分けられない。** 以下は傾き以外の根拠である。

### 往復の深さと、入力・出力・LLM時間

| 往復 | prompt p50 | completion p50 | LLM p50 |
|---|---|---|---|
| 1 | 29,757 | 538 | 7.63 |
| 2 | 29,892 | 779 | 7.81 |
| 3 | 30,043 | 749 | 6.10 |
| 4 | 30,258 | 899 | 9.58 |
| 5 | 30,450 | 1,136 | 11.85 |
| 6 | 30,654 | 1,533 | 13.78 |
| 7 | 30,901 | 1,465 | 15.50 |
| 8 | 31,223 | 1,123 | 11.61 |

```
入力  29,757 →  31,223   （+1,486／+5.0%）
出力     538 →   1,618   （+1,080／最大2.7倍）
LLM     7.63 →   15.50秒 （約2倍）
```

**1通目の入力 29,757トークンが 7.63秒で処理されている。**
そこに 5% 足しただけで 6秒増えることは、この数字と整合しない。

→ `task_next.md §1-3` の判定表：

> | `prompt_tokens` はほぼ一定なのにLLM時間が伸びる | **履歴ではない**（返事が長い／thinking が伸びている） | `completion_tokens` を見る。伸びていれば §3 の2（thinking_budget）が候補 |

**`completion_tokens` は伸びている。**

なお `completion_tokens` は thinking を含む（`thinking_budget: 1024`）。
**出力トークンが多いことは、返事が長いことを意味しない。**
返事の文字数は別に測っていない。
