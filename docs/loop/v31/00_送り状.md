### 1-3. **ただし、失敗が見えにくくなっています。ここはお知らせしておきたいところです**

§0 は「1往復目の `パラメータ抽出` に `__is_success: 1` が出ている」を確かめるように書かれていました。
**版z では、`__is_success` というキー自体が出てきません。**

| | 版y（第30版） | 版z（今回） |
|---|---|---|
| `__is_success` | `0` が出る | **キーが無い** |
| `__error` | 429の文が出る | **キーが無い** |
| `error_message` | — | **ここに429の文が入る** |

| `contact_safety_risk` | `None` | **`"0"`** |

**「429は解消した」と早合点しました。** 返事も173字あったので、ふつうの返事に見えたのです。

### 1-4. **`support_need` が 0 に落ちます。ここが心配です**

失敗したとき、`support_need` は取れないのではなく **`"0"` になります**。`contact_safety_risk` も `"0"` です。

```
1通目に送った文：母の介護をひとりでしています。最近、母に強く当たってしまいます。
  → support_need = "0"  contact_safety_risk = "0"
```

**ふつうなら 7 が付く訴えに、0 が付いています。**

いまは LLM も同時に落ちているので定型文が返りますが、
**もし `パラメータ抽出` だけが失敗して本文のほうが動いた場合、
その方は「いちばん困っていない人」として扱われることになります。**
枠を外す判断も、危機の速報も、着地の判定も、この数値で決まっているはずです。

**これは私の読みです。** 節点の中身は見ていません。**確かめるのは人の手でお願いします。**
「失敗したときは 0 ではなく、前の回の値を引き継ぐ」「失敗と分かる値にする」など、
決め方は人が決めることだと思います。
