### 指示の script から1つだけ変えた点（先に書きます）

**`response_mode` を `blocking` から `streaming` にしました。** 理由：

```
この実行環境のプロキシは、POSTを30秒で切ります（昨日の §5 安全確認で5往復が
これに当たりました）。1通目は中央値58秒なので、blocking では切れる公算が高い。

切れると usage が取れません。そして GET /messages には**単価が入っていません**
（message_tokens / answer_tokens / total_price / currency のみ。確認済み）。
つまり切れたら単価は取れず、第7版 §3 が禁じている2往復目が必要になります。

ストリーミングなら30秒の切断を受けないことは、昨日の測定で確認済みです。
`message_end` の metadata.usage は blocking の metadata.usage と同じものです。

**変えたのは受け取り方だけで、投げた内容・往復数・利用者IDの形は指示のままです。**
**作業側の手元では、この差し替えは要りません。**
```
