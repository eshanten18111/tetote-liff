そのとおりです。私は1件の実測値を上限のように扱いました。

**180秒を超える経路が理屈の上で存在する**ことは私にも確かめられたはずです。

これが本質的な指摘です。私の案は**幅を減らすだけで、問題の形を変えていません。**

## 3. PR #2 に軽微な不具合がありました（修正済み・PR #3）

### 確認したこと

`sanitizeName` を `origin/main` から取り出して試しました。
コロンの除去・20文字制限・既存 `sanitize` との組み合わせは**すべて意図どおり**です。

| 入力 | 出力 |
|---|---|
| `みさき：DV` | `みさきDV` ✅ |
| `みさき:DV` | `みさきDV` ✅ |
| `みさき／年代：99` | `みさき/年代99` ✅ |
| `やま\だ` | `やまだ` ✅ |
| あ×30 | あ×20 ✅ |

項目の境目の偽装は、コロン除去と `／`→`/` 変換の**二重**で塞がれています。

### 見つかった不具合

```
NG サロゲートペアの割れ: あり
   末尾: U+D842
```

**`.slice(0, 20)` は UTF-16 の単位で切ります。**
20文字目に絵文字や異体字（`𠮷` `🌸` など）が来ると**ペアが半分で割れ**、
末尾に不正な文字（`U+D842` 単独）が残ります。

`maxlength="20"` も同じ数え方なので、入力欄では防げません。

### 実害

小さいです。呼び名を20文字ぴったりにし、かつ20文字目が絵文字・異体字の方に限られます。
ただし**その1文字で文字化けが台帳まで届き、相談員が見る名前が壊れます。**

### 直し方

```js
function sanitizeName(v) {
  return [...sanitize(v).replace(/[：:]/g, '')].slice(0, 20).join('');
}
```

`[...文字列]` はコードポイント単位で分解するので割れません。
**絵文字を1文字として数えるようになり、利用者から見た「20文字」とも一致します。**

### 検証

`tools/dify-test/t_sanitize_name.js` に置きました。
`index.html` から関数を取り出して走らせているので、**本番のコードそのもの**を試しています。

```
OK 20文字目が異体字: 割れなし / 文字数=20
OK 20文字目が絵文字: 割れなし / 文字数=20
OK 絵文字だけ 25個: 割れなし / 文字数=20
（既存の8ケースも全件パス）
```

PR #3 を作成しました。急ぎではありません。
