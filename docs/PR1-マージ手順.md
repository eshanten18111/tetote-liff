# プルリクエスト #1 のマージ手順

対象：https://github.com/eshanten18111/tetote-liff/pull/1

所要時間は5分ほどです。マージ自体はボタン1つですが、
**反映の確認まで済ませて完了**としてください。

---

## 0. マージ前に：何が変わるかの確認

**本番の動作が変わるのは `index.html` の1ファイルだけです。**
31ファイル・2,339行の変更がありますが、残りはドキュメント（`docs/`）と
テストスクリプト（`tools/dify-test/`）で、利用者の画面には一切影響しません。

### `index.html` で変わること

入口フォームの送信前に、入力値からこの3つを取り除きます。

| 対象 | 処理 | 理由 |
|---|---|---|
| バックスラッシュ `\` | 取り除く | Difyの事前情報の抽出が全項目とも空になる |
| 制御文字（改行・タブ等） | 取り除く | 項目の切れ目が壊れる |
| 全角スラッシュ `／` | 半角 `/` に置換 | 項目の区切りに使っている文字のため |

### ⚠️ これは利用者の入力を黙って書き換えます

呼び名に `\` を含めた方には、**その文字が消えた状態で登録されます。エラーは出しません。**

意図的な設計です。相談窓口の入口で「その文字は使えません」と弾くより、
静かに整えて通すほうがよいと判断しました。
**この方針でよろしければ、マージへ進んでください。**

## 1. マージする

1. https://github.com/eshanten18111/tetote-liff/pull/1 を開く
2. 「**Files changed**」タブで `index.html` の差分を確認する
   （他のファイルはドキュメントとスクリプトなので、流し読みで構いません）
3. 「**Conversation**」タブに戻る
4. 緑の「**Merge pull request**」を押す
5. 「**Confirm merge**」を押す

### マージ方法について

ボタンの右の「▼」で選べます。**どれでも構いません**が、迷ったら既定のままで大丈夫です。

| 方法 | 向いている場合 |
|---|---|
| Create a merge commit（既定） | 作業の経緯を残したい |
| Squash and merge | 履歴を1つにまとめてすっきりさせたい |

## 2. 反映を確認する

マージしただけでは、利用者が開くページはまだ古いままの場合があります。

### 2-1. main に入ったか

https://github.com/eshanten18111/tetote-liff/blob/main/index.html

`sanitize` という語で検索し、**見つかれば main には入っています。**

### 2-2. 公開ページに反映されたか

`index.html` がどこから配信されているかによって、確認先が変わります。

**GitHub Pages の場合**

- リポジトリの「Settings」→「Pages」で、公開元のブランチが `main` になっているか確認
- 反映には**数十秒から数分**かかります
- 「Actions」タブに `pages build and deployment` が出ていれば、その完了を待つ

**別のホスティング（Cloudflare Pages 等）の場合**

そちらの管理画面で、デプロイが走ったかを確認してください。

### 2-3. ブラウザの表示を確認する

公開URLを開き、**ページのソースを表示**して `sanitize` を検索します。

> 見つからないときは、キャッシュが残っています。
> **Ctrl + Shift + R**（Mac は **Cmd + Shift + R**）で強制的に読み直してください。

## 4. うまくいかないときの戻し方

**何か問題が起きたら、迷わず戻してください。** 元に戻すのは安全です。

1. マージしたプルリクエスト（#1）を開く
2. 下のほうにある「**Revert**」ボタンを押す
3. 新しいプルリクエストができるので、それをマージする

これで `index.html` はマージ前の状態に戻ります。
ドキュメントとテストスクリプトも一緒に戻りますが、
**必要ならこの手順書の履歴から取り出せます**ので、心配は要りません。
