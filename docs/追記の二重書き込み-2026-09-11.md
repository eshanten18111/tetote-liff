# 追記が2回書き込まれる件と、前回報告の訂正（2026-09-11）

Worker のソースがリポジトリに追加されたことで、前回の報告の誤りが分かりました。
訂正と、あらためて見つかった問題を記録します。

---

## 1. 訂正：追記の本文は失われていません

### 前回お伝えしたこと（誤り）

> 相談者の言葉ではなく、固定文字列「受付しました」が台帳に入っています。
> 支援経過シートの既存の追記行が「受付しました」になっていないかご確認ください。

**この報告は取り下げます。** 既存の追記行を確認していただく必要はありません。

### 実際はどうなっていたか

Worker が追記本文を **GAS へ直接送っていました。**

```js
// worker/tetote-line-dify.js  recordForm()
if (mode === 'note') {
  payload.addendumText = f.noteText || '';   // 相談者が書いた本文そのもの
}
...
await postToGas(env, payload);
```

**追記の本文は、Worker 経由で正しく台帳に入っています。**

### なぜ誤ったか

私は `form2.html` が送る合図（`追記フォーム回答：受付しました`）と、
Dify 側の `addendum.py` だけを見て判断しました。
**Worker がフォームの中身を直接 GAS へ送る経路を見ていませんでした。**

当時 Worker のソースはリポジトリに無く、私からは読めない状態でしたが、
**読めない部分がある以上「確認してほしい」と問うべきで、
断定すべきではありませんでした。**

## 2. あらためて見つかった問題：GAS への書き込みが2回起きています

1回の追記に対して、**2つの経路から GAS に書き込まれています。**

| 経路 | 送られる `addendumText` | 中身 |
|---|---|---|
| Worker → GAS（直接） | `f.noteText` | 相談者が書いた本文 ✅ |
| Worker → Dify → GAS | `"受付しました"` | **中身のない行** ❌ |

### なぜ2回目が起きるか

`form2.html` は、フォーム送信後にトークへ合図の1行を流します。

```js
var MARKER = {
  note:  '追記フォーム回答：受付しました',
  close: '追記フォーム回答：受付しました'
};
```

Worker はこの合図を**そのまま Dify へ渡しています**（`askDify(env, userId, text)`）。
除外していません。

その結果 Dify 側の追記経路が動き、`addendum.py` が前置きを外して
「受付しました」を取り出し、GAS へ送ります。

### 実データ（本番で確認）

```
[追記本文抽出] addendum_text : "受付しました"
               addendumText  : "受付しました"
               rescue        : "追記の本文：\n受付しました"
[HTTP リクエスト（相談記録登録：追記）] {"ok":true,"queued":1}
```

### 影響

**データは失われません。緊急ではありません。**
ただし支援経過シートに「受付しました」だけの行が積まれ、
**相談員が見るシートにノイズが混ざります。**

また、追記の退避Slack通知が飛んだ場合、本文が「受付しました」となり、
**手で写す手がかりになりません。**

### 確認していただきたいこと

支援経過シートで、本文の行と「受付しました」の行が**対で並んでいないか**。

---

## 3. 対処案

| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| ア | Worker 側で合図を Dify に渡さない（`askDify` の手前で弾く） | 経路が減る | **Dify からの受領返信（「追記いただいた内容を承りました」）も出なくなる** |
| **イ** | **Dify 側で `stage: addendum` の GAS 送信をやめる** | 返信は残り、記録は Worker に一本化される | Dify 側のノードを1つ外す作業が要る |

**イをお勧めします。** 記録の経路が一本になり、
「どちらが正か」を考えずに済みます。利用者への返信も変わりません。

イを採る場合、Dify 側で不要になるもの：

- `HTTP リクエスト（相談記録登録：追記）`
- `コード（追記本文の組み立て）`（`addendum.py`）
- `コード（追記保存の結果判定）` と、その失敗分岐

**「追記フォーム回答」を受けて受領の返信を出す部分は残してください。**
