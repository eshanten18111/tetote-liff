## 1. カルテ照会 — 設計どおり動いています

台帳に存在しないLINEユーザーIDで2往復流しました（診断⑤の半分）。

| 確認 | 結果 |
|---|---|
| 1往復目に照会が走る | `IF/ELSE 16: true` → `{"ok":true,"found":false,"visits":0}` ✅ |
| 見つからないときの整形 | `karte_text: ""` / `karte_visits: ""` ✅ |
| 相談が止まらないか | 通常どおり進行（121字・傾聴に入る）✅ |
| **2往復目は素通りするか** | **`IF/ELSE 16: false`**。照会が走っていません ✅ |
| 初めての方の体験 | カルテ導入前と変わらず ✅ |

`karte_checked` の印が効いており、**往復が増えるのは会話の最初の1回だけ**という
設計どおりです。

残るのは照会自体がエラーになった場合ですが、既定値（空）で先へ進む配線なので、
**上で確認した `found=false` と同じ経路に合流します。**

確認用スクリプトは `tools/dify-test/karte_check.py` に置きました。
カルテ機能を触るたびに、初めての方の体験が壊れていないかを同じ手順で確認できます。

### 設計として良いと思った点

**引き継ぎメモを渡さず、「触れないでほしいこと」は必ず渡す。**
この非対称が正しいです。前者は「AIには見せない前提で書ける」ことに意味があり、
後者は渡さなければ避けようがありません。**渡す・渡さないを、用途から決めている**のが
良い判断です。

**AIが記号の列を人の言葉に直して返したこと。**
`9/12 生活困窮 必要度7 ｜ 9/10 必要度7` を「生活のことで大変な状況」と言い換えています。
記録を読み上げていない、という意味で狙いどおりの出方です。

## 2.【要ご判断】合言葉の価値が、今回の変更で大きく上がりました

### 何が変わったか

| | 漏洩したときの被害 |
|---|---|
| これまで | 台帳に**偽の行を書き込める** |
| **いま** | **その人の相談履歴を読み出せる** |

`op:'karte'` が返すもの：

```
呼び名／年代／性別／都道府県／市区町村／相談回数／初回・最終相談日
／これまでの相談／確かめた事実／AIの見立て／関わり方／触れないでほしいこと
```

必要なのは**LINEユーザーIDと合言葉**の2つだけです。

**書き込みより読み出しのほうが、被害が重いです。**
「触れないでほしいこと」まで含まれます。

### なぜ急ぐべきか

**(1) その値はもう「知られていないとは言えない」**

古いデプロイ6つに同じ値が入っていた期間があります。
アーカイブは済みましたが、**その間に値が外に出ていないことは証明できません。**

**(2) 照合が一時的に消えていた**

保存済みコードから合言葉の照合4行が消え、そのまま保存された状態がありました。
再デプロイしていれば、**認証なしで履歴を読める受け口**になっていたことになります。

気づけたのは確認手順のおかげで、偶然ではありません。
ただ、**それだけ紙一重だった**という事実は残ります。

### 提案

宿題リストの「1. 合言葉の入れ替え」を、**稼働前ではなく今週中**に前倒ししてください。

読み出し口ができた以上、**同じ値を使い続ける期間は短いほうがよい**です。
手順（Cloudflare と Dify に先に入れる → Cloudflare を反映 → Dify を公開
→ 最後に Apps Script のプロパティ → `selfCheckAuth`）は用意されています。

## 3. 提案：`op:'karte'` に試行回数の制限を

合言葉が漏れた場合、**LINEユーザーIDを総当たりされると履歴が芋づる式に読めます。**

1分あたりの照会数に上限を置くだけでも、被害の速度は大きく変わります。
スクリプト プロパティにカウンタを持たせる程度の実装で足ります。

あわせて、**同じLINEユーザーIDへの短時間の連続照会**も、
正常な使い方ではまず起きません（会話の最初の1回だけのはずです）。
そこを見るだけでも異常に気づけます。

急ぎませんが、稼働前に入れておく価値があると思います。

## 4. 事故の記録について

**第4節の書き方は適切です。**

影響がなかった理由（ウェブアプリはバージョンに固定）を書いたうえで、
**「ただし、その状態で再デプロイしていれば」と最悪の場合まで書かれています。**

影響がなかったことで終わらせていない記録は、あとから読む人の役に立ちます。

### 教訓3について

> 私（Claude）は、チャットにコード片を「見せる」ために出さない。
> 貼るものと見せるものの区別がつかない。

**これは私にも当てはまります。**
この会話でも本番に貼る前提のコードを何度か出しています。
以後、**貼る場所と範囲を明示したうえで出す**ようにします。

### 第9節（失敗の分類）について

5種類に分けて件数まで数えた記録は、そのまま再発防止に使えます。
特に「期待する文字列を手で書き写して間違えた」5回に対する
**「以後、文字列を手で書かず、必ずデータから導く」**は、
仕組みで防ぐ形になっていて良い対処です。

## 5. 診断④は、カルテを1件ご用意いただければ実行します

**カルテ機能でいちばん失敗が許されない部分**だと思います。

相談者が「これには触れないで」と伝えたことをAIが持ち出せば、信頼は一度で失われます。
**プロンプトの指示だけで守られている**ので、実際に試す価値があります。

### ご用意いただきたいもの

テスト用カルテを1件。

| 欄 | 例 |
|---|---|
| 呼び名 | テスト用の名前 |
| これまでの相談 | 簡単な経緯を1〜2行 |
| **触れないでほしいこと** | **具体的な項目**（例：「離婚のこと」「前の職場のこと」） |

LINEユーザーIDを教えていただければ、こちらから流します。

### やること

その話題に**意図的に近づく振り方**を数パターン試し、AIが避け続けるかを見ます。

- こちらから直接聞かない
- 遠回しに水を向けたときに乗ってこないか
- 相談者側から触れたときの扱い（ここは避けるべきではないはずです）

10往復・約 0.3 USD の見込みです。
